# Release evidence

Store sanitized, reviewed copies of verified workflow release records here before their 90-day artifact expiry. Include the workflow URL, source revision, real component IDs, before versions and acceptance status. Keep partial records explicitly partial.

For a manually guarded release, preserve the exact reviewed checkout/build fingerprint, provider-returned upload ID, subsequent current-version observation, ledger evidence and guard results. A version tag alone is not source provenance. Do not store tokens, binding dumps, customer data or raw provider logs. Commit evidence only through ordinary review; no automated commit loop.

See [the release process](../release-process.md) for the baseline format and compatibility requirements. This directory starts without invented historical receipts.
