# Route resources

TECH-11A loads Editor, HandyStudio, BusinessStudio, CollectionReview and Checkout through `src/routes/client-views.mjs`. App still owns the providers, photos, basket, personalisation drafts, checkout details, draft warning and Undo lifetime. The loader stores component code only.

`src/ssr.jsx` supplies `serverRouteViews` from an eager server-only registry. The existing synchronous SSR/prerender/live render APIs keep returning full markup. Initial public direct `/studio` preserves that markup until its Editor resource is ready, then hydrates the matching first render. Other initial public routes and authenticated admin preview use their existing `createRoot` entry. Public and authenticated admin preview share the same App and client registry. Preview forms remain disabled by the existing form service.

The route hook ignores obsolete completions, reuses fulfilled/in-flight imports and evicts rejected promises. Loading/error UI stays inside the shell. Route focus and section scrolling wait for readiness, while existing dialog, Undo and security recovery focus guards still apply. An explicit retry loads only code. It never retries a form submission or reloads the tab. Browsers may cache a failed module response, so repeated failure keeps the error and navigation available rather than discarding drafts. Initial editor and locked-order errors offer home; other route errors offer the designer.

TECH11A kept all CSS eager; TECH11B1 now defers only Checkout's Leaflet and locker-picker styles. Handy, gallery finish/game, mixed/global, home, seasonal and button styles remain eager. The two duplicate eager App imports are removed; their unchanged stylesheets stay imported by LockerPicker/NearbyLockerMap beneath Checkout. No stylesheet rules, tokens or build configuration change. Compare CSS source hashes and the common-plus-checkout cascade with the matching baseline, including admin preview. No other route stylesheet partition belongs to B1.

## Cold public studio handoff

`src/routes/bootstrap.mjs` applies only to initial exact `/studio` with real prerendered studio markup. Its promise continuation primes the existing Editor registry and waits before attaching React. It must not use entry-level top-level await: the generated Editor chunk imports shared exports from main. Home does not request this heavy view.

Native contact name/email/message, studio notes, disclosure state, selection/focus/scroll and file intent can change while code is loading. The matching first hydration render retains server defaults; controlled contact/notes are adopted into their actual owners in layout effects afterward. This avoids replacing the full studio with the short route status or hydrating nonempty photo/notes markup against empty SSR. A focused or scrolled native page keeps its viewport. Photo preparation may make the workbench inert; original notes/control focus is restored only while no newer pointer or keyboard action owns it.

Once entry code is running, the bounded waiting-phase handlers support only the existing studio chooser/input and file-drop zone. File references stay in browser memory. App adopts the batch once using the same exported capacity/readPhoto/format/error preparation as ordinary Editor uploads. Text/URL drops with no files leave the selected batch unchanged; an explicit empty native input change still cancels it. A newer native selection supersedes an unfinished startup batch; only that batch's temporary photo URLs are released. Kept photo identities and URLs survive normal basket/Undo navigation. Successful adoption removes the temporary handlers and releases the raw startup references. No file-change/action replay, persistent draft storage, submission, courier or email operation is introduced.

The resource controller has a15-second deadline. Failure leaves native SSR edits available with explicit Retry and Home actions. A late expired completion cannot attach App or silently make the failed attempt ready. Home/latest navigation transfers text/notes/raw files to one App; pending selected photos are shown accurately until explicit recovery, and do not produce a false empty basket. The original failed Editor is not retried automatically. Other routes retain their existing readiness, focus and memory rules. A browser may cache a failed module response, so retry does not guarantee that an unavailable deployed chunk will recover.

JavaScript-disabled behavior and the interval before entry execution retain ordinary native-browser limitations. Common direct CSS is still render-blocking. The handoff does not promise pre-JavaScript chooser/error UI, production CWV/INP or a performance score. Authenticated preview keeps its existing entry mechanism and disabled form service.

`ROUTE_STARTUP_ONLY=1` selects actual-built startup checks in `tests/route-loading.browser.mjs`, including default/saved catalogue/active-season contexts, held/failed code, native text/files, latest selection/navigation, focus ownership, validation, Undo and deadline/Home recovery. Use the matching `dist/client`, `dist/ssr` and manifest. All responses are local synthetic fixtures; external requests, unexpected APIs, storage and submissions are blocked. `ROUTE_RESULTS` saves evidence and `ROUTE_CASE` selects one diagnosis. The ordinary route fixture and full existing checks remain separate acceptance.

## Checkout stylesheet resources

Client and Admin builds emit separate Vite manifests. The public manifest survives the SSR build. Shared pure composition derives Checkout's static CSS closure, removes eager entry CSS and rejects unsafe or empty route metadata. Prerender and synchronous live rendering link the selected stylesheet before common CSS and add a safely escaped inert catalogue meta element. New live products and root templates receive the same correct composition. Admin prepare adds its separate catalogue; authenticated preview GET/HEAD composition uses the existing preview path parser, preserves policy/status, removes stale body-length/ETag, and keeps HEAD bodyless. Every referenced route CSS asset must exist at build time.

The client registry awaits CSS before importing Checkout. This prevents Vite's preload helper appending a duplicate after common/button overrides. A stylesheet link's presence is not readiness: the adapter awaits load/error, checks its sheet and bounds missed failures to 15 seconds. Explicit retry removes failed links and retries the same resource URL. Successful links remain cached before common overrides across history and reverse visit order. Missing production catalogue fails checkout safely. Development retains normal Vite CSS/HMR behavior. No loading/retry action remounts App or replays a submit. An old deployed chunk that no longer exists can remain failed while work stays in the tab.

Conventional direct-route stylesheet links remain render-blocking. Slow CSS can delay first paint; this tranche adds no critical CSS, streaming or guaranteed pre-JS error UI.
