# Read-only admin deployment diagnosis

Use this only to investigate the existing admin settings pre-upload read. It does not publish Pages, Admin or Security, change a credential, install a binding, alter customer records or send email. Keep the ordinary pre-upload protection guard enabled.

The workflow is manual, main-only and requires the full reviewed main SHA. It verifies the dispatch SHA, checkout SHA and current remote main before the only credential-bearing step. The job uses the existing `CUSTOMVIBE_PAGES_DEPLOY_TOKEN` secret and only `contents: read` GitHub permissions. It performs one GET of the pinned business Admin Worker's settings. There is no package installation or upload command.

After current-head required CI and independent review, normally merge this diagnostic change. The ordinary main push publishes Pages assets through the existing workflow; application source and assets are unchanged. Observe that publication and check current main and provider health before dispatching **Diagnose existing admin settings read**, with `expected_sha` set to that exact merged main SHA. Do not dispatch against an unreviewed revision or retry a failed publication blindly.

Output is one bounded JSON record. `READ_OK` proves only that the settings API read succeeded. It does not establish the protection bindings, deployed version, application acceptance or publication success. Other categories are `CONFIGURATION_ERROR`, `HTTP_ERROR`, `API_ERROR`, `INVALID_JSON`, `TIMEOUT`, `DNS_ERROR`, `TLS_ERROR` and `NETWORK_ERROR`. An HTTP status and up to five distinct numeric Cloudflare error codes may accompany a rejection. Provider messages, status text, URLs, headers, response/settings contents, binding values, token values and exception text are never included. Numeric codes alone may not establish the cause; use current official API documentation to interpret them before proposing an owner credential action.

The opt-in diagnostic transport rejects writes and migration sockets. Normal credential-maintenance and deployment callers retain their generic safe error message and existing operation restrictions. A diagnostic success must be followed by the unchanged normal protection preflight before any separately sequenced admin publication.
