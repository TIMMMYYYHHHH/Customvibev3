## Design Context

### Users
CustomVibe's owner manages unpaid magnet requests, checks print quantities and artwork, downloads print files and manually emails progress updates. These flows were explicitly requested by Tim.

### Brand and direction
Preserve the approved Happy Chaos / Little Thread direction, Fredoka headings and DM Sans body text. The working admin uses warm neutral surfaces, plum text and restrained berry/mint/lilac accents. Clear quantities and readable forms take priority over decorative elements.

### Implementation defaults
Existing React 19 and plain scoped CSS, native form controls, Phosphor icons when useful. No new UI library. Keep public storefront styles isolated from admin.

### Principles
Use one obvious action per context. Group artwork by design and separate print quantity from file count. Keep customer data private, visible only when needed. Make mobile controls and keyboard focus usable. Never use em dashes or diagonal arrows.

Use plain inline guidance for warnings and limits. Tim rejects "nail cards": boxed notices with thick accent side stripes. Do not add tinted alert boxes or decorative side borders. Match the existing surrounding typography, colours and spacing.

Owner button preference, confirmed 17 October 2026: avoid the glowing appearance created by a darker coloured border around a lighter tinted fill with matching coloured text. Do not use inset shadows or glow effects on controls. Use solid primary/selected controls with contrasting text, and flat neutral secondary controls. Keep keyboard focus visible and preserve distinct selected, hover and disabled states. Apply across customer and admin interfaces without changing approved brand layout.

Owner-approved admin consistency direction, 17 October 2026: Orders, Store content and Themes & seasons share AdminChrome and workroom.css. Keep the same wordmark, header, navigation, Sign out, page heading scale, spacing and flat controls across these pages. Preserve each page's existing functional layout and the approved order-stage colours. Do not reintroduce page-specific header overrides or standalone demo headers. Local visual approval precedes publication of this revision.

The confirmed no-glow preference also applies to order status badges, quantity labels and panels, not only buttons. Avoid darker matching coloured outlines on pale tinted fills and similarly coloured text. Keep the approved stage-colour card fills, use neutral text/dividers and solid contrasting status badges, and retain keyboard focus.

Owner button decision, 18 October 2026: use P1 Soft sticker with S1 Fresh mint across customer-facing controls. Main actions are solid berry #ae2e5b with white Fredoka text; secondary actions and unselected options use Fresh mint #9ddcc4 with deep plum #291438 text; selected options are plum with white text. Use softly squared 14px corners, flat fills, no glow, gradients, decorative outlines or shadows. Preserve readable disabled states, visible keyboard focus, quiet/destructive action hierarchy and mobile target sizing. Reuse src/button-system.css and docs/design/button-system.md for future components and the shared admin storefront preview. This supersedes the earlier neutral customer-secondary rule. The separate admin workroom retains its approved operational styling. Do not restyle F1 flags or print artwork as buttons.

Owner extension, 18 October 2026: apply the approved P1 / Fresh mint button system to the admin workroom as well. This supersedes the earlier instruction to retain neutral admin secondary buttons. Reuse src/button-tokens.css via admin/workroom.css: berry primary, mint secondary, plum selected, softly squared 14px corners and flat fills. Keep destructive/quiet controls, neutral disabled states and visible focus distinct. Preserve admin layouts, order-stage colours, warning messages, data, manual email actions and seasonal settings.
